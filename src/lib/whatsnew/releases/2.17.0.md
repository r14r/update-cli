# What's new in Update CLI 2.17.0

## Crash-safe update transactions

Update CLI now persists an on-disk transaction journal under `.update-cli/transactions/` before mutating deployment state. The journal records the transaction ID, current phase, source/target versions, current staging path, recovery path, activation state, and whether Docker services were running.

## Atomic current activation

Real updates no longer synchronize the new release directly into the live `current/` directory. Update CLI now:

1. creates `current.next-<transaction-id>`,
2. prepares and verifies the complete new current tree there,
3. runs project setup against the staged tree,
4. records the exact recovery path in the transaction journal,
5. activates the staged tree using directory renames,
6. starts services and runs the healthcheck,
7. commits the transaction and removes the previous current tree.

This keeps the live `current/` tree unchanged until activation.

## New `recover` command

Interrupted update transactions can be recovered explicitly:

```bash
update-cli recover
update-cli recover --json
```

Recovery uses the persistent journal to restore the previous current tree, discard incomplete staging, and restart a Docker Compose stack that was running before the interrupted update.

## Auditable transaction IDs

Successful updates, failed updates, and recovery operations now carry a transaction ID in history entries so update events can be correlated with recovery state.

## CLI and CI consistency

The Just recipes now use the canonical command-first CLI syntax for restore, verify, and setup selectors. CI now prints the exact unformatted files and `gofmt` diffs when formatting validation fails.

## Recovery regression coverage

Tests cover known-path atomic directory swaps, recovery after an interrupted activation, recovery before activation, transaction journal parsing, and the updated 14-phase fullscreen update flow.
